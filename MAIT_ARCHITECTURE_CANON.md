## 1. STRATEGIC CONTEXT

**Current sprint:** Tutor V1 — a 1-1 tutoring exoskeleton for Mental Maths Mentor, replacing Darra's Custom Gems/GPTs. The classroom-teacher dogfood (3-week SLSO coverage) is complete; UI friction at 30-student scale parked that surface. The 1-1 tutor is now the sole V1 user with guaranteed weekly dogfood.

**Why Gems/GPTs lose:** context-window amnesia, no native spaced repetition across weeks, long typed prompts mid-session. MAIT wins on: persistent per-student mastery state, pre-session zero-typing briefs, one-tap in-session actions, automated post-session distillation.

**Phase 2 (deferred):** student-facing access via tutor-mediated tethering, classroom/teacher surface, substitute-teacher day-pass wedge, WebLLM/SLM multi-tier routing, avatar/engagement layer, Vertex AI migration.

## 4. RETRIEVAL CONTRACT (LOCKED)

```sql
SELECT * FROM vector_chunks
WHERE subject = :class_subject
  AND metadata_json->>'topic' = :topic     -- exact match; topic comes from corpus-fed dropdown
ORDER BY embedding <=> :query_vector        -- cosine distance
LIMIT 3;
```

- Query vector = `gemini-embedding-2` @ 768 over (refinements, or topic string if refinements empty).
- **NO `year_level` filter** (ruled out — unnormalised data; subject string already scopes the course).
- **NO distance cap** for V1 (0.35 cap rejected: verified good matches sit 0.21–0.29 distance; a cap starves loosely-worded queries).
- Topic dropdown is fed by: `SELECT DISTINCT metadata_json->>'topic' FROM vector_chunks WHERE subject = :subject AND metadata_json->>'topic' IS NOT NULL`.
- Free-text from the user maps to **refinements** (semantic ranking), never to the topic filter.
- Open-ended/chat-intent queries with no selected topic: subject-only filter + cosine (looser by design, never ungrounded). ⚠️ VERIFIED 12/06/2026 — NOT AS BUILT: `/api/chat/generate` (`routers/chat.py`) requires `topic` (Pydantic `min_length=1`) and ALWAYS applies `subject = :subject AND metadata_json->>'topic' = :topic`, LIMIT 3; there is no subject-only fallback path in code. Chat free text rides in `refinements` and is used as the embedding text (`refinements or topic`); the frontend disables chat send until a topic is selected. The ruling above stands as the target behaviour; the gap is logged in docs/AUDIT_2026-06-12.md — implementation requires Darra-sanctioned work, not an audit fix.

## 7. TUTOR V1 PRODUCT CONTRACT (RULED)

**The loop:** Pre-session brief → in-session deck → post-session dump.

1. **Pre-session brief (zero typing):** dashboard per student per session: current mastery snapshot, due retrievals (overdue topics ranked), active friction (Mistake Vault highlights), last-session delta, and a **pre-generated deck** — 3-question trap/retrieval warmup + main set on planned topic + challenge reserve. All generation latency lives here, not mid-session.
2. **In-session (cards, taps, command bar):** full-screen question card (KaTeX), answer behind a tap, outcome buttons (✓ nailed / ~ struggled / ✗ bombed / skip) — each tap writes `question_log`. Long-press outcome → misconception chip (auto-suggested from student's Mistake Vault). Modifier buttons: More-like-this / Step-down / Step-up (the only mid-session generation). **Command bar:** one slim, always-available input as versatile as a GPT/Gem prompt box — curveball question in, card out. No conversational thread UI.
3. **Post-session:** one messy brain-dump box → Flash-Lite extraction pass → proposed structured deltas (mastery transitions, vault entries, summary update) → **tutor reviews/edits before commit** (explicit-assertion rule as UI). Parent report generated from committed state on demand.
4. **Traffic-light syllabus map:** corpus topic list (grid) LEFT JOIN topic_mastery (colour): grey unseen, red/amber/green by status. Per-student. Dot-point drill-down is Phase 2.

**Mastery state machine (CONSTANTS RULED):**
- Statuses: `unseen → introduced → shaky → solid → mastered`.
- Promotion: 2 consecutive ✓ at current level (mastered promotion should span ≥2 sessions).
- Demotion: 1 ✗ drops one level and schedules next-session reinforcement.
- Retrieval intervals: shaky → next session; solid → 2–3 weeks; mastered → 6 weeks (resurfaces as challenge/checking).
- **Negative-RAG correction:** `mastered` suppresses a topic from NEW-TEACHING generation but is exactly what the RETRIEVAL pool draws from once overdue. Never hard-block mastered topics — that deletes spaced repetition.
- Implementation: a SQL view + constants. NO SM-2, no scheduler service, no per-item ease factors.

**Memory architecture (two-tier, Vesper-derived with corrections):**
- Tier 1 — rolling profile: bounded, curated, tutor-editable, always injected as `{student_context}`.
- Tier 2 — episodic timeline: Flash-Lite extraction (dual-pass) into structured objects, semantically retrievable.
- **Explicit-assertion rule:** mastery/vault writes require demonstrated evidence (an outcome tap, observed work). Extractor never infers states; unverified = NULL. Tutor-editable ledger UI is the QA mechanism.
- Vesper's SQLite + Markdown-file watchdog is NOT ported (local-agent pattern). Relational state = Postgres; editability = ledger UI; Markdown = export format for parent reports only.
- Pseudonymisation middleware (real names → slugs before any external API call, rehydrated for display): ruling pending (R2) but architecture must not preclude it.

## 8. STRICT GUARDRAILS

**NEVER:**
- NEVER use SQLite/`aiosqlite` for active logic, or FAISS/sentence-transformers anywhere.
- NEVER embed queries with any model other than the ratified corpus model (`gemini-embedding-2` @ 768).
- NEVER filter retrieval by `year_level`; never query JSONB as `metadata`.
- NEVER alter `vector_chunks` structure, re-chunk, or re-embed without Darra's ruling.
- NEVER force `[N Marks]` onto questions; never withhold worked answers on tutor-facing surfaces.
- NEVER name textbook sources as truth in prompts or ingest textbook content (copyright).
- NEVER hard-block `mastered` topics from generation (suppress from new-teaching only).
- NEVER remove React Router; never use float sort keys (LexoRank only); never inline styles.
- NEVER skip `--no-shell-escape` for `pdflatex` subprocesses.
- NEVER create an `app/models/` package alongside `app/models.py`.
- NEVER commit mastery/vault state without evidence (explicit-assertion rule).
- NEVER ship multi-tier SLM/WebLLM routing in V1. Hardcode Gemini Flash.
- NEVER offer Extension 1/2, Science, or IB in the UI while absent from the corpus.

**ALWAYS:**
- ALWAYS chain Alembic migrations off the single current head; review autogen before upgrade.
- ALWAYS validate `tutor_id` ownership through the centralised access dependency on every route (IDOR).
- ALWAYS `.format()` every placeholder an intent template declares.
- ALWAYS keep generation grounded in retrieved chunks; admit gaps in a `text` part.
- ALWAYS use Tailwind utilities; auto-save fragment edits on 2-second idle debounce; humanise LaTeX errors via Gemini before surfacing.
- ALWAYS write user-facing copy in Australian English, warm, direct, peer-level, zero edtech jargon.
