## 3. Contradictions Found (repo vs DECISION layer — reported, not acted on)

**C1 — "FAISS DEAD" vs eager live imports.** Canon §2 rules FAISS dead and "removable legacy". Reality: `import faiss` executes on every boot through the legacy student path; `faiss-cpu` + `sentence-transformers` still install from `requirements.txt` (the latter pulls torch — material against the canon's own 512MB host constraint); the startup banner still says "RAG system enabled (FAISS backend)". The code is not removable by deletion alone: `/query`, `/interact`, and `educational_agent.py` depend on it. Resolving requires a ruling (see §4).

**C2 — Chat-intent subject-only retrieval is not implemented.** Canon §4 rules that no-topic chat queries run a subject-only filter. As built, `topic` is mandatory end-to-end (Pydantic 422 + disabled UI) and every retrieval is exact-topic-filtered. The ruling is currently aspirational; building it is sprint work, not an audit patch.

**C3 — `MAO-WM-01` exclusion has no enforcement mechanism in code.** Canon §3 states Working Mathematically is "excluded from topic lists". The `/api/topics` query (`routers/chat.py`) selects ALL distinct topics with no exclusion clause, and no ingestion script (`ingest_to_pgvector.py`, `generate_json.py`, `normalize_db.py`) references `MAO-WM` at all. Either WM content was never chunked with a topic value (probe 2 will tell), or it will appear in the dropdown. If probe 2 finds it, the fix needs a ruling on where exclusion belongs (ingest-time vs query-time).

**C4 — Durable corpus JSON not committed.** The two-step pipeline's durable artifact (`corpus/syllabus.json`) is an empty placeholder in git. Not a ruling violation per se, but it undermines the recovery story the pipeline design implies. Needs a ruling: commit the JSON, or bless `.docx` + scripts as the only recovery path.

## 4. Contested Decisions (reasoning only — no action taken)

**D1 — "Any FAISS/MiniLM code found in repo is removable legacy" understates the coupling.** Removing FAISS is not a deletion task; it is a decommissioning decision about the legacy student surface (`/query`, `/interact`, `educational_agent`, `syllabus_service`). Options for the ruling: (a) delete the legacy student routes outright (students are out of scope this phase); (b) port `syllabus_service` to pgvector and keep the routes; (c) quarantine behind lazy imports so `faiss` only loads if a legacy route is hit. My recommendation is (a) or (c) — (a) is cleanest under the current strategic context, (c) is a 10-line change that gets `faiss-cpu`/torch out of the boot path and could precede the full decision. Also recommend dropping `faiss-cpu` and `sentence-transformers` from `requirements.txt` whenever the chosen option lands (512MB host).

**D2 — VERIFY-6 contract nuance worth a micro-ruling.** The frontend's renderer supports a `title` on parts and the prompt contracts would benefit from titled glass-box cards, but the Pydantic model omits `title`, so Gemini structured output can never emit one. Either add `title: Optional[str]` to `ExoskeletonResponsePart` (one line, plus prompt mention) or strip the dead `part.title` path from the renderer. Cosmetic, but it is a live mismatch between the two halves of the locked contract.
